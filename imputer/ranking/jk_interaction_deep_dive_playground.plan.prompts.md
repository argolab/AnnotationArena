## Prompt G1 — Bundle rewrite missingness ladder (ratings-only first)

**Motivation**
We want reusable missingness patterns (easy→hard) for JK-only experiments without repeatedly modifying Stan generation. We already have `data_bundle.json` where `all_ratings` is the full universe, and `observed_ratings`/`missing_ratings` define the observation split. We want to “hack” missingness by rewriting those lists, then run Marformer + Stan unchanged on the rewritten dataset.

**Current repo context**
- Bundles are generated by `stan/scripts/generate_data.py` and saved via `stan/pipeline/io.py:save_bundle(...)` into `OUTPUT/generated_data/<run_name>/data_bundle.json`.
- `data_bundle.json` includes `all_ratings`, `observed_ratings`, `missing_ratings`, `stats` (and pairwise fields, which we can ignore initially).
- Training/Inference scripts that should work unchanged on rewritten bundles:
  - Marformer: `imputer/run_imputer.py --data-dir <dataset_dir>`
  - Stan baseline: `stan/scripts/run_inference.py --data-bundle <dataset_dir>/data_bundle.json` + `stan/scripts/evaluate_predictions.py`
- Bundle validation helper exists: `imputer/data.py:DataConverter.validate_bundle(...)`.

**Task**
1) Add a CLI script (place it somewhere stable like `stan/scripts/rewrite_missingness.py` or `scripts/rewrite_missingness.py`) that:
   - Loads `INPUT_DIR/data_bundle.json` and `INPUT_DIR/configs.json`.
   - Recomputes `observed_ratings` and `missing_ratings` by selecting a subset of entries from `all_ratings` as observed.
   - Updates `stats` consistently (observed/missing counts; train/test observed rates; and metadata like `stats["rewrite_protocol"]`, `stats["rewrite_params"]`, `stats["rewrite_seed"]`).
   - Writes `OUTPUT_DIR/` with:
     - copied `configs.json`,
     - rewritten `data_bundle.json`,
     - optional `README.md` snippet recording the rewrite command.
   - Keep it **ratings-only** first (don’t rewrite pairwise yet); preserve existing pairwise lists as-is.

2) Implement these rewrite patterns (ratings-only):
   - `mcar_iid`:
     - parameter: `--missing-rate` (or `--observed-rate`), seed-controlled sampling uniformly over rating entries.
   - `balanced_degree_mcar`:
     - parameters: `--missing-rate`, `--min-degree-annotator`, `--min-degree-item`.
     - enforce degree constraints in the **train observed** bipartite graph first, then fill remaining observed edges to match target rate.
   - `annotator_block`:
     - parameters: `--missing-rate`, `--block-fraction-annotator`, `--block-missing-fraction`.
     - choose a subset of annotators and drop most of their ratings; keep the complement relatively well observed.
   - `item_block`:
     - parameters: `--missing-rate`, `--block-fraction-item`, `--block-missing-fraction`.

3) CLI usability requirements:
   - `--input-dir` and `--output-dir` required.
   - `--pattern` selects one of the patterns above.
   - `--seed` for reproducibility.
   - Help text includes 2–3 runnable examples, e.g.:
     - “Generate JK base data via `scripts/easy_data/easy_JK.sh`”
     - “Rewrite into MCAR 50% missing”
     - “Rewrite into annotator-block missingness”

**Non-goals (explicitly defer)**
- Do NOT implement `connectivity_controlled` or MNAR patterns yet. Those are gated on diagnostics (G2) showing topology is predictive of failure.

**Acceptance criteria**
- Rewritten dataset passes `DataConverter.validate_bundle` (no overlaps; observed+missing partitions cover all_ratings; indices in range).
- `imputer/run_imputer.py` runs unchanged when pointed at `OUTPUT_DIR`.
- `stan/scripts/run_inference.py` + `stan/scripts/evaluate_predictions.py` run unchanged when pointed at `OUTPUT_DIR/data_bundle.json`.
- `stats` in the rewritten bundle matches realized counts and includes rewrite metadata.

## Prompt G2 — JK bipartite diagnostics infra (matrices + rank-1 plots + correlation plots)

**Motivation**
When Marformer underperforms Stan in JK-only, we need infrastructure that localizes the gap: which annotators/items, whether low-degree nodes drive it, and whether the error surface is approximately low-rank (separable J×K). This should run on every dataset variant and produce standardized artifacts for diffing.

**Current repo context**
- Marformer outputs `OUTPUT/IMPUTER/<run_name>/predictives.json` written via `imputer/utils.py:build_predictives(...)`.
  - For ratings, each prediction entry includes: `annotator`, `items` (length 1), `instance`, `status`, `rating_probabilities`, and `true_rating_class` (if available).
- Dataset bundle `.../data_bundle.json` provides observed/missing split and is needed to compute the **train-observed** J–K topology.
- Existing plotting script `utils/visualize.py` exists, but this request is specifically for **JK diagnostics** (new script).

**Task**
1) Add a new script (suggested: `utils/jk_diagnostics.py`) that takes:
   - `--data-bundle path/to/data_bundle.json`
   - `--imputer-predictives path/to/predictives.json`
   - `--out-dir path/to/output_dir` (default: sibling directory near predictives, e.g., `<run_dir>/jk_diagnostics/`)
   - optionally `--slice` (default: `test_missing` ratings).

2) Compute JK metric matrices on the default slice (ratings only):
   - `JK_logloss[j,k]`: average negative log probability assigned to the true class.
   - `JK_acc[j,k]`: average correctness (argmax vs true).
   - `JK_rmse[j,k]`: RMSE of predicted rating vs true rating on the chosen rating scale; record which scale is used (e.g., `1..C`) in output metadata.
   - Also compute `JK_count[j,k]` (number of entries aggregated into each cell).
   - Aggregate across attributes `i` (since `hold_I_constant=1`) but keep counts so sparse cells are handled safely.

3) Rank-1 approximation probes (one-to-one with each matrix):
   - For each `M ∈ {JK_logloss, JK_acc, JK_rmse}`, fit rank-1 `M ≈ u ⊗ v` with NaN/weight handling.
   - Produce a **rank-1 summary plot** per metric with:
     - central heatmap for `M` (original matrix),
     - an x-axis histogram/line plot of `v` aligned with K,
     - a y-axis histogram/line plot of `u` aligned with J.
   - Produce a companion residual heatmap `M - u⊗v`.
   - In captions/README text, explicitly interpret `u`/`v` as **proxy contribution vectors** under the separability assumption (independent J and K contributions). Emphasize that each rank-1 PNG corresponds to one metric matrix.

4) Topology summaries from **train-observed** graph:
   - Build J–K bipartite graph where an edge exists if any rating observed for that `(j,k)` in train (optionally weight by count across attributes).
   - Compute: degree distributions for annotators and items; number of connected components; giant component fraction; isolates.

5) Correlation analyses (deliverable plots must be explicit):
   - For annotators:
     - scatter: `deg(j)` vs `avg_logloss(j)`, `avg_rmse(j)`, `avg_acc(j)` (computed on test-missing slice).
   - For items:
     - scatter: `deg(k)` vs `avg_logloss(k)`, `avg_rmse(k)`, `avg_acc(k)`.
   - Each scatter plot should include a best-fit line (or LOWESS), and annotate Pearson + Spearman.
   - Add **binned trend plots**:
     - degree deciles on x-axis, mean metric on y-axis, error bars (std/sem), and counts per bin.

6) Standardized artifacts (stable filenames):
   - `jk_diagnostics.json` (summary stats, correlations, metadata about scale and slice)
   - `jk_matrix_logloss.csv`, `jk_matrix_acc.csv`, `jk_matrix_rmse.csv`, `jk_matrix_count.csv`
   - `plots/`:
     - `jk_heatmap_logloss.png`, `jk_heatmap_acc.png`, `jk_heatmap_rmse.png`
     - `jk_rank1_approx_logloss.png`, `jk_rank1_approx_logloss_residual.png`
     - `jk_rank1_approx_acc.png`, `jk_rank1_approx_acc_residual.png`
     - `jk_rank1_approx_rmse.png`, `jk_rank1_approx_rmse_residual.png`
     - `degree_vs_logloss_annotator.png`, `degree_vs_logloss_item.png`
     - `degree_vs_acc_annotator.png`, `degree_vs_acc_item.png`
     - `degree_vs_rmse_annotator.png`, `degree_vs_rmse_item.png`
     - `degree_binned_vs_metric_annotator.png`, `degree_binned_vs_metric_item.png`

7) Optional integration:
   - Add a lightweight call at the end of `scripts/easy_data/easy_JK.sh` after Marformer produces `predictives.json`, so each run auto-generates diagnostics (no changes to model training).

**Acceptance criteria**
- Works on an existing JK run directory and produces the matrices + plots without modifying training.
- Plots directly answer: “are low-degree annotators/items driving the JK gap?” and “does the error look separable (rank-1)?”

## Prompt G3 — Optimization/sample-efficiency experiments (safe curricula + drift test + subset-forward)

**Motivation**
We want to test whether the JK gap is largely optimization/sample-efficiency (not representational). We will not change model class; we’ll change training dynamics and supervision density, while avoiding leakage.

**Leakage constraint**
Do NOT implement curricula that reveal labels for entries that are later evaluated as missing on the same instance, unless those entries are excluded from evaluation (never-seen holdout).

**Current repo context**
- Training masking is applied in `imputer/lightning_trainer.py:ImputerLightningModule._apply_training_mask` via `self.masking_rate`.
- The Lightning dummy dataloader length is `mask_augmentations`; each step forwards over (masked/observed + missing vars).
- CLI entrypoint: `imputer/run_imputer.py`.

**Task**
1) Add masking schedule support (safe curriculum):
   - Add CLI flags in `imputer/run_imputer.py` and plumb into `ImputerLightningModule`:
     - piecewise or linear schedule for `masking_rate` over epochs,
     - schedule for `mask_augmentations` over epochs (bounded, deterministic).
   - Log effective values each epoch/step in TensorBoard and/or the JSON history already written by the run.

2) Add a non-leaky pretrain→mask “drift” experiment mode:
   - Implement a way to partition the rating universe into 3 disjoint sets:
     - `S_train_obs_base` (always observed),
     - `S_curriculum_extra` (observed only in Phase 0),
     - `S_holdout_never_seen` (never supervised; always evaluation target).
   - Run two phases in one command:
     - Phase 0: train with `S_train_obs_base ∪ S_curriculum_extra` observed.
     - Phase 1: continue training with only `S_train_obs_base` observed; treat `S_curriculum_extra` as missing inputs.
   - Evaluation must be on `S_holdout_never_seen` throughout; optionally track metrics on `S_curriculum_extra` as a drift probe but do not use it for checkpoint selection.
   - Note: this may be implemented either as a dataset rewrite (G1 service) producing two bundle variants + a training driver that chains them, or as a training-time supervision selector.

3) Implement “subset-forward” for larger J/K (density boost under fixed compute):
   - Add a training mode where each step samples an induced subgraph subset:
     - sample a subset of annotators and items, include only variables touching them,
     - enforce minimum diversity (e.g., at least A annotators and B items),
     - keep evaluation unchanged (still evaluate on full test variables).
   - Log per-step token counts so we can confirm compute reduction.

4) Provide example flag grids (documentation only; no sweep runner required):
   - baseline vs scheduled masking
   - baseline vs subset-forward
   - drift-test enabled vs disabled

**Acceptance criteria**
- Default behavior unchanged if new flags are not passed.
- With schedules enabled, logs clearly show changing `masking_rate`/`mask_augmentations`.
- Drift-test mode produces a trace showing whether holdout metrics degrade during Phase 1 (drift) or remain stable.
- Subset-forward reduces tokens per step while training and evaluation still run.

## Prompt G4 — Inductive bias experiment (bilinear JK head + ordinal structure)

**Motivation**
If Marformer still lags Stan under friendly missingness + strong optimization, the remaining gap may be representational: Stan assumes structured JK interaction (dot-product latent utility + ordinal thresholding). We want to inject minimal inductive bias and measure how much the gap closes (especially where diagnostics show rank-1 structure).

**Current repo context**
- Core model: `imputer/ranking_imputer.py:MultiVariableImputer` produces rating logits per variable.
- Training loop: `imputer/lightning_trainer.py` + `imputer/losses.py:DefaultLossStrategy`.
- Predictives: `imputer/utils.py:build_predictives`.

**Task**
1) Add an optional auxiliary bilinear JK head for ratings (flag-gated):
   - Learn (or predict) annotator embeddings `u_j` and item embeddings `v_k` (attribute-invariant for JK-only).
   - Utility `s = u_j^T v_k (+ bias)`.
   - Map `s` to Likert via ordinal thresholds (ordered logit/probit style) or a monotone mapping.

2) Training:
   - Add an auxiliary loss on observed+masked ratings for this head.
   - Combine with existing loss via a configurable weight (e.g., `--bilinear-head-weight`).

3) Evaluation + outputs:
   - Report metrics for: (a) main head, (b) bilinear head, (c) optional ensemble.
   - Extend `predictives.json` schema to optionally include bilinear probabilities/predictions (without breaking existing consumers; e.g., add new keys).

4) Keep scope minimal:
   - Don’t redesign batching.
   - Don’t add new baseline models (Stan remains the baseline).

**Acceptance criteria**
- Feature is off by default; baseline runs unchanged.
- With the feature enabled, training runs end-to-end on JK data and emits comparable metrics.
- G2 diagnostics can be run to see whether the bilinear head reduces structured JK error (esp. low-degree slices / rank-1-shaped failures).
