# Baselines: STAN Posterior Inference Models

The two STAN generative models that produce our synthetic datasets also serve as oracle baselines.
Running MCMC inference on the observed data gives posterior predictive distributions over missing
ratings — the best possible predictions under each model's assumptions.

---

## Why These Are the Right Baselines

The synthetic datasets are generated by these exact models, so the STAN posteriors represent the
theoretically optimal predictor for each dataset family. If Entity Marformer achieves STAN-level
performance on a given split, it has matched the oracle for that generative model.

Performance below STAN indicates the neural model has not fully captured the structure of the
data. Performance equal to STAN means the model has learned what STAN knows. Performance above
STAN on held-out data would indicate STAN is underfit (unlikely given it generated the data).

---

## Baseline 1: Normal Model

**STAN file:** `STAN/stan_models/normal_noise_dot_product_model.stan`

**Applies to:** `Normal_250_20_9_AnnotatorTest`, `Normal_650_20_9_ItemTest`

**Generative assumption:**
```
V_ij ~ N(v_i, σ² I)    (spherical Gaussian annotator noise)
z_ijk = V_ij · e_k
r_ijk ~ OrdinalProbit(z_ijk, thresholds)
```

**Inference:**
Given the observed ratings, MCMC recovers the posterior over `v_i`, `e_k`, `V_ij`, and
the cut-point thresholds. The posterior predictive `P(r_ijk | observed)` is used as the
prediction for each missing rating.

**Oracle ceiling for Normal data.** A neural model trained on Normal data should approach
but not substantially exceed the Normal STAN posterior on held-out ratings.

---

## Baseline 2: Factor Model

**STAN file:** `STAN/stan_models/normal_noise_dot_product_model.stan` (with `use_factored_annotator=1`)
**Generation file:** `STAN/stan_models/normal_noise_dot_product_generation.stan`

**Applies to:** `Factor_250_20_9_AnnotatorTest`, `Factor_650_20_9_ItemTest`

**Generative assumption:**
```
u_j ~ N(0, I_{d_annotator})    (annotator embedding)
M_i ~ N(0, I)                   (attribute-specific transform)
V_ij = v_i + u_j · M_i          (structured annotator deviation)
z_ijk = V_ij · e_k
r_ijk ~ OrdinalProbit(z_ijk, thresholds)
```

**Inference:**
The factored annotator model has more structure — each annotator's behavior across all attributes
is governed by a shared low-dimensional embedding `u_j`. MCMC recovers posteriors over `v_i`,
`u_j`, `M_i`, `e_k`, and thresholds.

**Oracle ceiling for Factor data.** Factor data has more annotator structure than Normal data,
so Factor STAN should be a harder target for neural models (and more rewarding when matched).

---

## Running Inference

```bash
# From imputer/ranking
bash scripts/STAN/run_inference.sh
```

This script runs STAN MCMC on a specified data bundle and writes posterior predictive
distributions to `*_posterior_rating_probs` in the bundle JSON.

The inference results are what appear in the bundle as `train/val/test_posterior_rating_probs`
and are used by `scripts/STAN/evaluate_predictions.py` to compute baseline accuracy metrics.

---

## AnnotatorTest vs ItemTest: What STAN Can Predict

**AnnotatorTest:**
STAN has seen all items during training. When test annotators are new, STAN can still
form a posterior over their preference vectors (given their observed ratings) and predict
their missing ratings. The factor model does this particularly well via `u_j`.

**ItemTest:**
STAN has seen all annotators during training. When test items are new, STAN must predict
their embeddings `e_k` from scratch using only the observed ratings for those items.
Since test items are entirely new, STAN forms posteriors only from the test-split
observed ratings — it has no prior information on `e_k` beyond the overall embedding distribution.
This is why `rating_dist` is absent for test items: STAN has no posterior to record.

---

## AnnotatorTest Baseline Variants (Stan Model File)

For AnnotatorTest, the inference model (`normal_noise_dot_product_annotator_gen.stan`) is
designed specifically for the AnnotatorTest split structure:
- All items are shared (one embedding matrix `[K, D]`).
- Annotators are partitioned into train/val/test groups; posteriors are computed per group.
- Output: `train/val/test_posterior_rating_probs` of shape `[I*J_split, K, C]`.
